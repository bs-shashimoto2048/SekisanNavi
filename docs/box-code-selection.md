# 箱コード自動選定

図面情報の各盤について、接続情報・箱体型式・盤寸法から部品台帳の箱コード
(品名「箱･単独」「箱･左右」「箱･中」)を1つ選び、盤ごとに積算明細(`estimate_results`)へ追加する。

実装: `backend/app/domain/box_code_selection.py`(選定規則、純粋関数)、
`backend/app/services/box_code_candidates.py`(盤・寸法の解決と積算結果候補への変換)、
`backend/app/repositories/estimate_box_overrides.py`(手修正の保存)、
フロント `frontend/src/components/EstimateDetail/EstimateBoxCodeCell.tsx`。

## 選定規則

| 入力 | 規則 |
|---|---|
| 接続情報 BAN_CONNECT | `箱･単独`→箱･単独 / `箱･左右(L)`・`(R)`→箱･左右 / `箱･中央`→箱･中。NFKC・空白・中点の全半角だけ正規化。未知・空欄は推測せず要確認 |
| 型式 | 製番の箱体型式から既存の `parse_box_type` で第1記号(例 `OS2`)を解決。マスタ型式はハイフンがあれば最初のハイフンより前だけ(`OS2- 816`→`OS2`)、なければ全体(`OA`)と完全一致。NFKC |
| 定格 `H*W*D` | **m単位**(`2.3*0.9*2.0`)。盤寸法(mm)へ ×1000 して照合 |
| 定格 `H*W*D1～D2` | 奥行の範囲(両端を含む)。例 `2.3*0.5*0.7～0.9` |
| 定格 `H+W+D=N` | **mm単位**。BAN_H1+BAN_W+BAN_D がちょうど N のときだけ一致 |
| 付記 `:両開` | 寸法照合から除外 |
| 高さ | 定格 2.3m は 2300〜2399mm を一致 |
| 奥行 | 定格どおり(単値はちょうど) |
| 幅 | 実幅と同じ定格幅があればそれ、無ければ実幅を含む次の定格幅(1.3m→1.4m)。実幅がその型式・高さ・奥行の最大定格幅を超えれば該当なし |
| 使う寸法 | BAN_H1(正面高さ)・BAN_W・BAN_D。BAN_H2(背面高さ)は使わない |

候補が1件に定まれば自動選定。0件・複数件・解釈できない定格(同じ第1記号の型式に1件でもあれば)・
寸法未設定・第1記号を解決できない場合は、コードを選ばず「要確認」にする。

### 盤寸法(画面と同じ規則)

画面の盤情報(`frontend/src/domain/panelDimensions.ts`)と同じ規則をBackendに移植している。

1. estcode_df.csv の BAN_W/BAN_D は正の値のみ有効(0・欠損は未設定)。
2. 未設定の項目は、product_df.csv の「ZUMEI に『外形図』を含み BAN_TYPE が『正面図』」の行
   (ページ昇順、BAN_MENNO+BAN_NO 一致、項目ごとに最初の正の値)で補う。
3. 正面高さ(BAN_H1)も上記の行から。正面・背面とも無いときだけ estcode_df.csv の BAN_H。
4. どれも無ければ未設定(要確認)。

## 積算明細への反映

- 行の識別: `result_key = box:面番号:盤番号`。物理盤(面+盤)につき1行、数量1、`judgment_scope=panel`、
  対象盤にひも付く。価格は部品台帳の `総合価格A` をそのまま使う(値が無ければ空のまま)。
- 要確認の行: `code=''`・`master_item_id=NULL`・`status=needs_review`・価格なし。
- 製番を開いたとき、箱の行がまだ無い製番は1回だけ評価して追加する(`App.tsx`)。箱の行がある製番では
  再評価しない。以後は図面検出の操作ごとの再評価・`POST .../estimate-results/evaluate` で再選定される。
- 図面検出由来の明細と同じ盤・同じコードがある場合は、根拠なく合算・削除せず、双方を「要確認」にして
  両方残す(`mark_duplicates_with_detection_results`)。

## 手修正

- `PUT /api/products/{no}/box-selections/{面}/{盤}` `{"master_item_id": n}` で同じ盤の1件を置き換える
  (2件目は追加しない)。選べるのは箱3カテゴリのコードのみ。盤の品名カテゴリ(接続情報から決まる)が
  確定していれば同じカテゴリ内だけ(違えば422)。接続情報が不明な盤は3カテゴリすべて。
- `DELETE` で手修正を取り消して自動選定へ戻す。どちらも再評価後の積算結果一覧を返す。
- 手修正は `estimate_box_overrides`(製番×面×盤に1件)に保存され、再評価・画面再読込でも保持される。
  `estimate_results` は評価のたびに作り直されるため、手修正は評価時に読んで反映する。
  手修正したコードがマスタから消えた場合は自動選定へ戻る。

## 既知の制約

- 製番の箱体型式は、画面(PanelInfo)と同じく「型式が入っている最初の盤」の値を製番共通として使う。
  盤ごとに型式が異なる製番は考慮していない。
- 第1記号を解決できない型式(例: 現行の `box_type_parser` が未対応の `SS-…`)は要確認になる。
- 寸法は外形図・正面図の行から補う規則のため、その行が無い製番は寸法未設定で要確認になる
  (現在ページの行にだけ寸法がある場合、画面上は表示されても選定には使われない)。
- マスタの同じ型式・寸法に `H*W*D` と `H+W+D=N`(OA・IA)の両方が一致する場合は複数候補として要確認。
